## Trabalho realizado

- Instalação das dependências e criação de package-lock.json. Usar npm ci nas próximas instalações.
- Prisma CLI e Client fixados em 6.19.3: a seleção automática por latest instalava ferramentas incompatíveis com os comandos do projeto.
- Configuração ESM nos pacotes API e banco.
- Correção da sintaxe do schema e de 13 erros de relações. Removidos campos de relação sem contraparte que haviam sido inseridos em User e ServiceOrder; acrescentadas contrapartes de CompanySettings, notificações, agenda e vínculo orçamento/OS. Nenhum banco existente foi alterado.
- Geração de migration SQL inicial, com 1327 linhas, a partir do schema validado. Destino: banco NOVO e vazio; não aplicar a banco existente sem comparação, baseline e backup.
- A pasta antiga de migration continha somente instruções, sem SQL. Foi movida para docs/migration-notes-incrementos-9-10 para não ser interpretada como migration incompleta.
- Gate de homologação passa a resolver o diretório raiz corretamente.
- Corrigido uso da relação signatures no PDF da OS (assinatura mais recente) e tipo de status do pagamento.
- Guard global nas rotas internas rejeita tokens do portal e exige permissões de leitura/escrita nas rotas de financeiro e financeiro gerencial. Isto é contenção inicial, NÃO conclusão da revisão de RBAC de todo o sistema.
- Cinco testes adicionais exercitam hooks HTTP reais em aplicação Fastify isolada: ausência de token, token de cliente, técnico no financeiro, financeiro autorizado e administrador.

## Retomada técnica

Este checkpoint contém fontes, package-lock e migration, mas não node_modules, builds ou credenciais. Instalar com npm ci, gerar Client com npm --workspace apps/api run prisma:generate, executar npm --workspace apps/api run typecheck e npm --workspace apps/api test, e compilar frontend com npm --workspace apps/web run build. A execução de serviços e migrations depende do ambiente autorizado. As dependências não receberam auditoria completa de vulnerabilidades nesta etapa.
